# Netlify 认证限流路由修复

- 日期时间：2026-07-18 13:22:09 +08:00
- 影响范围：登录、注册、退出登录、截图上传的 Netlify Functions 路由

## 改动内容

- 将登录、注册和退出登录统一到 `/api/auth/:action` 动态路由。
- 保留认证接口每分钟 10 次的代码级限流，但由三个认证入口共享一条规则。
- 保留截图上传接口每分钟 12 次的独立限流规则。
- 将 `@netlify/functions` 从 3.1.10 升级到 5.3.0，使 `rateLimit` 成为受支持且可由 TypeScript 校验的正式配置。
- 删除认证和上传配置末尾用于绕过旧类型检查的 `as Config`，确保 Netlify 部署后处理可以静态提取路由与限流配置。
- 删除不再需要的独立 `auth-logout` Function，退出登录改由统一认证 Function 处理。
- 为统一认证路由和退出 Cookie 清理补充自动化测试。

## 修改原因

原实现使用的 `@netlify/functions` 3.1.10 类型尚不包含 `rateLimit`。代码通过 `as Config` 强制绕过类型检查后，Netlify 部署后处理没有提取到认证和上传 Functions 的自定义路由，部署仍显示成功，但 `/api/auth/login` 返回 404。认证路径数组还会形成登录、注册两条限流规则，再加上传一条，超过 Personal 套餐的两条上限。

## 解决的问题

- 将项目使用的代码级限流规则降为两条，符合当前套餐限制。
- 让不受支持或拼写错误的 Netlify 配置在本地构建阶段直接报错，不再静默部署缺失路由。
- 恢复登录、注册、退出登录和截图上传的自定义 API 路由。
- 继续保留防止撞库和批量上传滥用的限流保护。
