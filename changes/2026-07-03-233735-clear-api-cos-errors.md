# 2026-07-03 23:37:35 - 明确 API 与腾讯 COS 报错原因

## 改动内容
- 增强腾讯 COS 访问失败时的错误信息，返回操作类型、目标 COS 域名、底层网络原因和排查建议。
- 增强 COS HTTP 非 2xx 响应的错误信息，返回 HTTP 状态、COS 请求 ID、COS 返回内容摘要和状态对应的可能原因。
- 增加 COS 环境变量缺失、`COS_BUCKET` 填成完整域名、`COS_REGION` 填错格式时的明确提示。
- API 统一错误返回增加 `status` 字段，并在 Netlify Functions 日志中输出错误栈和底层 cause。
- 前端请求失败时区分“浏览器无法连接服务器”和“服务器返回错误”，避免只显示模糊的“请求失败”。

## 修改原因
- 之前腾讯 COS 网络失败时只显示 `fetch failed`，无法判断是 DNS、超时、连接重置、密钥权限还是配置错误。
- 用户在使用线上版本时需要能根据页面报错直接定位问题，减少反复查看模糊日志的成本。

## 解决的问题
- COS 域名解析失败会提示检查 `COS_BUCKET` 和 `COS_REGION`。
- COS 连接超时会提示 Netlify 到腾讯云跨云网络可能不稳定。
- COS 403/401 会提示检查腾讯云密钥和桶权限。
- COS 404 会提示对象不存在或桶/地域不匹配。
- 前端无法连接 API 时会明确提示网络或 Netlify 在线状态问题。

## 注意事项
- 错误信息不会输出腾讯云密钥本身。
- 如果线上仍然报错，需要根据新的错误文本继续判断是配置、权限还是网络问题。
